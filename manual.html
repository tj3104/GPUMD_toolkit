00概要と構成

GPUMD は GPU 上で動く分子動力学エンジンで、入力は model.xyz と run.in の 2 ファイル、出力は thermo.out や dump.xyz などのテキストファイルという構成をとる。 本ツールキットはこの入出力を Python 側から組み立て・読み取り、 subprocess で gpumd を起動する。

02構造の読み込み —StructureHandler · fastio

ase.io.read は汎用だが、原子数が増えると形式によって極端に遅くなる。 そこで読み込みは既定で高速経路を通る。 StructureHandler.read(..., fast=False) でいつでも従来どおりの ASE 経由に戻せる。

形式ase.io.read本ツールキット経路
CIF28.7 s 1.84 s / 2 回目以降 0.002 s pymatgen + xyz キャッシュ
POSCAR / CONTCAR13 ms3 ms numpy だけの専用パーサ
extxyz4 ms2 ms numpy だけの専用パーサ

Cu 4,000 原子 (ase 3.29 / pymatgen 2026.5.4) で実測した値。 python scripts/convert_structure.py <file> --benchmark で再現できる。

2.1xyz キャッシュ

CIF のような遅い形式は、一度読んだ結果を extxyz に変換して使い回す (cif2xyz / POSCAR2xyz 相当)。キャッシュのキーは 元ファイルの絶対パス + mtime + サイズなので、構造を書き換えれば自動的に 作り直される。保存先は cache_dir 引数 → 環境変数 GPUMD_TOOLKIT_CACHE → ~/.cache/gpumd_toolkit/xyz の順。

python
from gpumd_toolkit import cif_to_xyz, poscar_to_xyz, convert_to_xyz, read_fast
from gpumd_toolkit import StructureHandler

cif_to_xyz("big.cif")                  # -> big.xyz (入力の隣に作る)
poscar_to_xyz("POSCAR", "model.xyz")
convert_to_xyz("structure.pdb")

atoms = read_fast("big.xyz")           # 0.002 s
atoms = StructureHandler.read("big.cif")            # 初回だけ変換、以後キャッシュ
atoms = StructureHandler.read("big.cif", fast=False) # 従来どおり ase.io.read

python scripts/convert_structure.py big.cif --benchmark      # 予実 (どれだけ速いか)
python scripts/convert_structure.py --clear-cache

2.2セル形状のユーティリティ

GPUMD の model.xyz は 9 成分の lattice を取るので、 セルの形状に制限はない。ただし近接リストで効くのは辺の長さ ではなく 面間距離 (thickness = volume / 面積) なので、 スーパーセルの判定もそちらで行う。

python
StructureHandler.cell_thickness(atoms)    # 面間距離 (GPUMD の Box::thickness_* と同じ定義)
StructureHandler.classify_cell(atoms)     # 'cubic' / 'tetragonal' / ... / 'triclinic'
StructureHandler.is_triangular(atoms)     # ASE の NPT が要求する三角行列か
StructureHandler.to_standard_cell(atoms)  # 下三角形 (LAMMPS 標準形) へ剛体回転
StructureHandler.reduce_cell(atoms)       # Niggli / Minkowski 簡約

# min_cell_length は「面間距離の下限」として扱われる
calc = GPUMDCalculation("POSCAR", NEP, "runs/x", min_cell_length=12.0,
                        reduce_cell="niggli",   # 斜めのセルをできるだけ立方体に近づける
                        standard_cell=True)     # 下三角形に揃える

例: fcc Cu の菱面体プリミティブセル (a = 2.546 Å, 60°) は辺が 2.546 Å でも 厚みは 2.08 Å しかない。辺長で判定すると 5×5×5 で足りると誤認するが、 面間距離で判定すれば 6×6×6 が必要と分かる (NEP のカットオフ 6 Å の 2 倍)。

3.3熱浴・圧浴の時定数

GPUMD の <T_coup> / <p_coup> / tperiod / pperiod は 時間刻みを単位とする無次元量 (τ/Δt) であって時間ではない。 目安は T_coup ≈ 100、p_coup ≈ 1000、 pperiod ≥ 200。

無次元量をそのまま渡すことも、tau_T / tau_p に fs で渡して自動換算させることもできる。 tau_*/time_step < 1 は GPUMD が受け付けないのでその場で例外にする。 ステージごとに time_step= を変えた場合はそのステージの刻みで換算する。

python
calc = GPUMDCalculation("POSCAR", NEP, "runs/x", time_step=2.0)

calc.nvt(temperature=300, steps=10_000, T_coup=100)   # tau_T/dt = 100
calc.nvt(temperature=300, steps=10_000, tau_T=200)    # 200 fs / 2 fs = 100 (同じ)

calc.npt(temperature=300, steps=10_000,
         tau_T=200,     # 熱浴の時定数 [fs]
         tau_p=4000)    # 圧浴の時定数 [fs] (npt_mttk なら pperiod になる)

3.4セル形状と変調する軸

GPUMD はセルの形状そのものに制限を設けていない。制限があるのは NPT の 圧力指定の方で、成分の数でセルの動き方が決まる。

cell_mode圧力成分セルの動きセルの条件
iso1 (静水圧)体積のみ (等方)直交セル
ortho3 (xx, yy, zz)3 軸独立直交セル
tri6 (xx, yy, zz, yz, xz, xy)6 自由度すべて任意 (三斜晶可)

cell_mode を省略すると、構造が三斜晶なら自動的に tri に切り替える (直交セルなら pressure の 成分数から決める)。直方晶セルに直したい場合だけ GPUMDCalculation(..., orthorhombic=True) を使う。

python
# --- npt_ber / npt_scr: 固定したい成分の弾性率を 2000 GPa 超にする ---
calc.npt(temperature=300, steps=10_000, free_axes=("z",))     # c 軸だけ動かす
calc.npt(temperature=300, steps=10_000, fixed_axes=("xy",))   # xy 剪断だけ止める
calc.npt(temperature=300, steps=10_000, pressure=(5, 0, 0))   # x に 5 GPa
calc.npt(temperature=300, steps=10_000, cell_mode="tri")      # 6 自由度すべて

# --- npt_mttk: GPUMD 側の direction 指定をそのまま使う ---
calc.npt(temperature=300, steps=10_000, barostat="npt_mttk",
         mttk_direction="aniso")                        # 3 軸独立
calc.npt(temperature=300, steps=10_000, barostat="npt_mttk",
         mttk_direction="x", pressure=5.0)              # x に 5 GPa、他は固定
calc.npt(temperature=300, steps=10_000, barostat="npt_mttk",
         mttk_direction={"x": 5.0, "y": 0.0, "z": 0.0}) # 成分ごとに圧力
calc.npt(temperature=300, steps=10_000, barostat="npt_mttk",
         pressure=0.0, pressure_end=5.0)                # 圧力ランプ

npt_ber / npt_scr の軸固定は 「弾性率が 2000 GPa を超える成分はカップリングを 0 にする」という GPUMD 本体の仕様 (src/integrate/integrate.cu) を使っている。 実測でも free_axes=("z",) で 300 ステップ回すと a, b の標準偏差は 0.00 Å、c だけが 0.019 Å 揺らぐ。 npt_mttk で mttk_direction="x" にすれば a だけが動く。

calc.describe() は各 NPT ステージがどの軸をどう動かすかを表示する。

静的計算 — 弾性定数・状態方程式・フォノン

python
from gpumd_toolkit.workflows import StaticCalculation, band_path_kpoints

calc = StaticCalculation("POSCAR", "nep.txt", "runs/static", repeat=(2, 2, 2))
calc.relax(relax_cell=True)      # FIRE でセルごと最適化
calc.elastic(strain=0.01)        # 弾性定数 C_ij
calc.cohesive_curve(0.95, 1.05)  # 状態方程式
calc.single_point()              # エネルギー・力・応力
calc.run()

calc.elastic_matrix()            # 6x6 [GPa]
calc.elastic_moduli()            # B = 169.3 GPa, G = 61.1 GPa, E = 163.6 GPa, nu = 0.339
calc.energy_per_atom(); calc.forces(); calc.stress()
calc.equilibrium_from_cohesive()

# フォノン分散 (kpoints.in とスーパーセルが必要)
path = band_path_kpoints([[0,0,0], [0.5,0,0], [0.5,0.5,0], [0,0,0]], 50)

# HNEMD (最も効率がよい)

可逆スケーリングは「温度を上げる」代わりに「ポテンシャルを λ 倍に弱める」計算である。 古典系の配置分布は exp(−λU/kBT0) = exp(−U/kB(T0/λ)) なので、 λU の系を T0 で回すと、元の系を有効温度 Teff = T0/λ で回したときと同じ原子配置が得られる [5]。 そのため thermo.out の値は次のように見える。

  • 温度: 運動エネルギーは熱浴の Tmin のまま (上の Si の例では平均 301.7 K、Tmin = 300 K)。 Tmax には上がらない。G(T) の横軸は Tmin/λ から作る。
  • 圧力: ビリアルも λ 倍されるので、読み取れるのは λP 付近 (P = 0 なら 0 のまま)。
  • 体積・ポテンシャルエネルギー: Teff の系と同じように熱膨張し、U も増える。 融点を超える Tmax を取ると、温度が Tmin のままでも固体が融ける (5.8)。

以前の版の MDAnalyzer は ti_rs temp T_min T_max を昇温と誤読し、 temperature.png / overview.png の破線 “target” を Tmin→Tmax の直線で描いていた。 現在は Tmin 一定で描く (図の破線が実測温度と重なれば正常)。

AS は最初に平衡化しない

ti_as は ① の区間を持たず、ステージの最初から p_min → p_max へ動かす (t_equil は p_max 側と、復路のあとの p_min 側に置かれる)。 p_min・同温度の NPT 平衡化を直前のステージで済ませておく。

5.5液相 — Uhlenbeck-Ford + 可逆スケーリング、融点

参照系は Uhlenbeck-Ford 流体 (理想気体 + 軟らかい斥力)。GPUMD は理想気体項 (ド・ブロイ波長と密度) と多成分の理想混合項 Σ c ln c を含めた絶対値を出すので、 液体の混合物もそのまま扱える。固相と同じポテンシャルで液相の G(T) を作れば、 交点が融点になる。

5.6固溶体 — 部分対応

配置エントロピーは自動では入らない

固体中では原子が入れ替わらないので、Frenkel-Ladd が出すのはその 1 つの原子配置の 自由エネルギー (振動の寄与のみ) になる。GPUMD の ti_spring は液体の ti_liquid と違い混合項 Σ c ln c を含めない。ツールキットにも補正関数は無いので、 配置エントロピー Sconf は自分で引く (Gss = GFL − T Sconf)。

  • 理想混合 Sconf = −kB Σ xi ln xi はランダム配置の近似。 Cu0.7Au0.3 で 0.611 kB → 300 K で −15.8 meV/atom。
  • 短範囲規則 (SRO) があると実際の Sconf は理想混合より小さいので、この補正は過大評価になる。 厳密には SGC-MC による積分やクラスター展開が要る (ツールキットは未対応)。
  • 配置によるばらつきがあるので、ランダム配置を複数作って平均する (今回 2 配置で 2.7 meV の差)。
python
import numpy as np
from ase import units
from gpumd_toolkit.workflows import FreeEnergyCalculation, MonteCarloCalculation

# (任意) MC で短範囲規則を平衡化し、その最終構造 (restart.xyz) を使う

structure.arrays.pop("momenta", None)          # 速度は捨てて TI 側で与え直す

ss = FreeEnergyCalculation(structure, "nep.txt", "runs/fe_ss")
ss.equilibrate(temperature=300, steps=10_000, pressure=0.0)

ss.reversible_scaling(T_min=300, T_max=900, t_equil=4_000, t_switch=20_000)

5.7気相 — 単原子は対応、分子は非対応

専用のメソッドは無いが、単原子気体は uhlenbeck_ford() をそのまま 気体の密度で使えばよい。Uhlenbeck-Ford 参照系は低密度で理想気体に一致するので、 相互作用の分だけが TI で足される。

python
import numpy as np
from ase import Atoms, units
from gpumd_toolkit.workflows import FreeEnergyCalculation

T, p_atm = 300.0, 1.0
v = units.kB * T / (p_atm * 101325 / units._e * 1e-30)   # 理想気体の体積 [Å^3/atom]
n = 5                                                     # 5^3 = 125 原子を格子状に置く
L = (n**3 * v) ** (1 / 3)
grid = (np.arange(n) + 0.5) * L / n
gas = Atoms("Ar125", positions=[(x, y, z) for x in grid for y in grid for z in grid],
            cell=[L, L, L], pbc=True)

calc = FreeEnergyCalculation(gas, "nep89.txt", "runs/gas_Ar", time_step=2.0)
calc.nvt(temperature=T, steps=10_000)
calc.uhlenbeck_ford(temperature=T, t_equil=4_000, t_switch=20_000,
                    pressure=p_atm * 1.01325e-4)          # [GPa] G = F + PV 用
calc.run(analyze=True)
calc.gibbs_free_energy()      # F, G [eV/atom]
分子気体 (H2O など) は非対応

Uhlenbeck-Ford 参照系はばらばらの原子の流体なので、分子気体では TI の途中で 分子が解離する。往路と復路が大きくずれ (H2O 1 atm で rms 2 eV/atom)、結果は 古典理想気体 (並進 + 剛体回転子 + 調和振動子) の解析解から +1.75 eV/atom ずれた。 分子気体の G は、孤立分子の構造・振動数を NEP で求めて理想気体の式で出す (ASE の IdealGasThermo など)。

5.8注意点

  • hysteresis() を必ず見る。 正常時の rms は 0.01〜0.06 eV/atom 程度。 Si を融点 (1365 K) より上の T_max=2000 K まで可逆スケーリングしたところ、 折り返し点で固体が融けて rms 0.34 eV/atom になり、G(900 K) が 238 meV ずれた。 T_max は融点などの安定限界より下に取る (熱浴は T_min のままでも、有効温度 T_min/λ で融ける)。
  • ずれが大きければ t_switch を伸ばす (スイッチをゆっくりにする)。 上の値は t_equil=4000, t_switch=20000 ステップ。
  • エネルギーの原点はポテンシャルごとに違う。 相どうしの比較は同じポテンシャル同士で行う (nep89 では孤立 Ar 原子が −20.046 eV)。
  • pressure 引数は G = F + PV の計算にだけ使われる (ダイナミクスには効かない)。 体積は直前の NPT 平衡化で決まる。気体では実際の密度に対応する圧力を与える。 なお GPUMD の yaml は P を 6 桁で丸めるので、1 atm 程度だと P_GPa の表示は 不正確になる (G 自体は正しい)。
  • 古典統計である。 零点振動などの核量子効果は入らない (軽元素・低温では PIMD が必要)。

15設計メモ

  • 構造の読み込みは fastio の高速経路が既定。 POSCAR / extxyz は numpy だけの専用パーサ、CIF は pymatgen、それ以外は ASE。 遅い形式は extxyz に変換してキャッシュする。fast=False で いつでも ASE 経由に戻せる。
  • 入力生成は calorine (calorine.gpumd.write_xyz) を使用。 ASE の extxyz ライタは速度の単位換算 (ASE 単位 ↔ Å/fs) をしないため。 (fastio.write_xyz_fast は単位換算込みの軽量ライタで、 StructureHandler.write_model(..., fast=True) から使える。)
  • 時定数は GPUMD が τ/Δt という無次元量を取るので、 tau_T / tau_p (fs) は RunInputBuilder / MDStage の time_step を見て換算する。 ステージごとに刻みを変えた場合はそのステージの刻みを使う。
  • NPT の軸固定は npt_ber / npt_scr では 弾性率 > 2000 GPa、npt_mttk では direction の指定で 実現する。どちらも GPUMD 本体の仕様 (src/integrate/integrate.cu, doc/gpumd/input_parameters/ensemble_*.rst) に沿ったもので、 ツールキット側で積分器に手を入れているわけではない。
  • セルの厚みは volume / 面積 で評価する (GPUMD の Box::thickness_* と同じ定義)。 スーパーセルの判定も辺長ではなくこちらで行う。
  • 実行は subprocess + bash -lc "source <venv>/bin/activate && gpumd"。 GPU 指定は CUDA_VISIBLE_DEVICES。標準出力は gpumd.out に保存する。
  • 原子数は既定で 10,000 を上限とし、超えると例外 (mission の指示)。 min_cell_length を指定すると、NEP のカットオフを満たす最小のスーパーセルを 上限内で自動決定する。
  • run.in のキーワードは非 propagating (次の run に引き継がれない) ため、MDStage ごとに dump_thermo / dump_xyz を書き直している。 MDAnalyzer はこの構造を逆にたどって時間軸とステージを復元する。
